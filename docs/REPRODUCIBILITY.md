# Reproducibility

 Run commands from the repository root, in a clean checkout, and keep generated work outside tracked directories. `AF_WORK_ROOT` selects work/output dependencies, `AF_DATA_ROOT` locates acquired data and `AF_MODEL_DIR` identifies the pinned snapshot. Optional `AF_PATH_MAPPING` maps additional preserved metadata prefixes explicitly. The paths YAML is a documented example; it is not auto-loaded. Every registry input resolves relative to this repository, with no dependency on the developer's workstation or recovery directory.

 CPU verification: install requirements.txt, run `python -m pytest`; check all module --help commands and `python -m src.cross_regime.target_scoring.run --verify --package-only`. Analysis report commands start without GPU. Reconstruction itself needs the externally acquired raw sources and media, and LISTEN needs process-start PYTHONHASHSEED=42/Python3.12.

 EmotionTalk raw-prefix replay uses 19250 aligned T/A/V/M annotations and four source NPZ label archives, stratifies the five T/A/V topologies, selects 300 per pattern, then uses the frozen balanced Random(42) 14-sequence schedule for 1500 utterances. The multimodal label is descriptive, not a selection target. All four canonical boundaries passed the prior verified data-layer audit; frozen definitions are preserved and are not reaudited here.

 EmotionTalk Phase1 obtains model-derived labels and uncertainty for 4500 unimodal slots. Readable is parsed-label equality with the corresponding modality source label. DualReadable is their conjunction; Phase2 is conditional on this previous execution. The preserved source measurement table/population plan supports exact mainline reuse. Phase2 executes 2132 slots; Phase3 uses the frozen 402-slot plan with 67 utterances × six orders. Phase3 composition fields also depend on prior pairwise outputs. Fresh model execution is required to obtain new outcomes; this normal DAG is MODEL EXECUTION BY DESIGN. Do not redefine populations when preparing the mainline release.

 Current GPU launchers use confirmed input-construction, inference, continuation decoding and scoring kernels under semantic names. Historical gate-only mains and dynamic patch stacks are removed. Portable orchestration checks current release hashes and immutable model/processor content instead of replaying old execution-package path order or old gate-source file hashes. Results from a future launch must retain failed rows and receive independent completeness/identity closeout; this packaging task does not authorize new experiments.

 B3 exact assignment is read rather than regenerated. The raw scoring command emits `B3_FORWARD_RESULTS_V1.jsonl`, `B3_MEASUREMENTS_V1.jsonl` and `B3_ACQUISITION_COMPLETENESS_V1.json`. Run `python -m src.cross_regime.target_scoring.finalize --output-dir ../large_outputs/b3` to produce formal corrected CSV/provenance/hash files; raw distributions are never recomputed or rewritten by that step. The external mainline artifact catalog records exact sealed outputs and hashes. Evaluation reads the formal corrected bundle and recomputes scalar features on CPU before zero-refit predictions.

 Zero-refit evaluation reuses historical source scalers/coefficient order/intercept/pair offsets/shared FIRST_IS_MODALITY1/threshold0.5, frozen joint outcomes and support accounting. Full metrics are log loss (primary), AUROC, balanced accuracy and Brier (secondary). Target fitting, threshold tuning, calibration, subgroup exploration and ontology remapping are absent. Historical comparison values are a comparison-only reference; they are not current results or executable analysis code.

 External artifact requirements include raw datasets/media, the immutable Qwen snapshot, complete prior model outputs for new downstream reconstructions, ; minimal prepared source records for publication CV are included. The exact Phase3 plan and main-analysis summaries must be reused where the original producer was not recovered. Source code does not claim these missing writers have been reconstructed.

 Full GPU outputs are excluded from Git. Supply the sealed corrected bundle from local/archive storage and compare every listed hash in `frozen/identity/corrected_output_catalog.json`. A public archival URL can be added later without changing frozen measurements or results.

CA-MER media preparation reads `--data-root` and writes a new `--output-root` outside acquired inputs. Use `python -m src.reconstruction.camer.prepare_media --mapping /path/to/CAMER_MEDIA_MAPPING_V1.csv --data-root "$AF_DATA_ROOT" --output-root /path/to/new/camer-work`. The joint replay is `python -m src.cross_regime.run_camer_joint --output-dir ../large_outputs/camer` for CPU plan validation; append `--execute-gpu` only for a separately authorized execution with the frozen derived media in `AF_DATA_ROOT`. All portable orchestration changes are recorded in `docs/portable_orchestration.json`.
