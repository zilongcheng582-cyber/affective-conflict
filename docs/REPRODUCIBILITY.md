# Reproducibility

 Run commands from the repository root, in a clean checkout, and keep generated work outside tracked directories. `AF_WORK_ROOT` selects work/output dependencies, `AF_DATA_ROOT` locates acquired data and `AF_MODEL_DIR` identifies the pinned snapshot. Optional `AF_PATH_MAPPING` maps additional preserved metadata prefixes explicitly. The paths YAML is a documented example; it is not auto-loaded. Every registry input resolves relative to this repository, with no dependency on the developer's workstation or recovery directory.

 CPU verification: install requirements.txt, run `python -m pytest`; check all module --help commands and `python -m src.cross_regime.target_scoring.run --verify --package-only`. Analysis report commands start without GPU. Reconstruction itself needs the externally acquired raw sources and media, and LISTEN needs process-start PYTHONHASHSEED=42/Python3.12.

 EmotionTalk raw-prefix replay uses 19250 aligned T/A/V/M annotations and four source NPZ label archives, stratifies the five T/A/V topologies, selects 300 per pattern, then uses the frozen balanced Random(42) 14-sequence schedule for 1500 utterances. The multimodal label is descriptive, not a selection target. All four canonical boundaries passed the prior verified data-layer audit; frozen definitions are preserved and are not reaudited here.

 EmotionTalk Phase1 obtains model-derived labels and uncertainty for 4500 unimodal slots. Readable is parsed-label equality with the corresponding modality source label. DualReadable is their conjunction; Phase2 is conditional on this previous execution. The preserved source measurement table/population plan supports exact mainline reuse. Phase2 executes 2132 slots; Phase3 uses the frozen 402-slot plan with 67 utterances × six orders. Phase3 composition fields also depend on prior pairwise outputs. Fresh model execution is required to obtain new outcomes; this normal DAG is MODEL EXECUTION BY DESIGN. Do not redefine populations when preparing the mainline release.

 Current GPU launchers use confirmed input-construction, inference, continuation decoding and scoring kernels under semantic names. Historical gate-only mains and dynamic patch stacks are removed. Portable orchestration checks current release hashes and immutable model/processor content instead of replaying old execution-package path order or old gate-source file hashes. Results from a future launch must retain failed rows and receive independent completeness/identity closeout; this packaging task does not authorize new experiments.

 B3 exact assignment is read rather than regenerated. The raw scoring command emits `B3_FORWARD_RESULTS_V1.jsonl`, `B3_MEASUREMENTS_V1.jsonl` and `B3_ACQUISITION_COMPLETENESS_V1.json`. Run `python -m src.cross_regime.target_scoring.finalize --output-dir ../large_outputs/b3` to produce formal corrected CSV/provenance/hash files; raw distributions are never recomputed or rewritten by that step. The external mainline artifact catalog records exact sealed outputs and hashes. Evaluation reads the formal corrected bundle and recomputes scalar features on CPU before zero-refit predictions.

 Zero-refit evaluation reuses historical source scalers/coefficient order/intercept/pair offsets/shared FIRST_IS_MODALITY1/threshold0.5, frozen joint outcomes and support accounting. Full metrics are log loss (primary), AUROC, balanced accuracy and Brier (secondary). Target fitting, threshold tuning, calibration and ontology remapping are absent. The new post-audit condition/baseline/duplicate diagnostics are explicitly separated from the frozen historical evaluation. Historical comparison values are a comparison-only reference; they are not current results or executable analysis code.

 New model execution and raw-to-canonical reconstruction need lawfully acquired raw datasets/media and the immutable Qwen snapshot. Historical CPU replay needs only this repository: complete corrected probability vectors, projected observed Phase2/Phase3 responses, source measurements, source coefficients/scalers, frozen populations and composition plan are included. Original historical writers remain unrecovered; post-audit verification is a new independent consumer of existing evidence.

 The necessary formal successful GPU outputs are tracked under `evidence/b3`, with exact original hashes and a release-subset checksum. The old execution checksum is retained as provenance; it also lists unshipped logs/technical packaging files and is not the checkout completeness checksum. `EVIDENCE_MANIFEST_V1.json` and the current post-audit payload manifest bind the shipped subset. No public archival URL is invented.

CA-MER media preparation reads `--data-root` and writes a new `--output-root` outside acquired inputs. Use `python -m src.reconstruction.camer.prepare_media --mapping /path/to/CAMER_MEDIA_MAPPING_V1.csv --data-root "$AF_DATA_ROOT" --output-root /path/to/new/camer-work`. The joint replay is `python -m src.cross_regime.run_camer_joint --output-dir ../large_outputs/camer` for CPU plan validation; append `--execute-gpu` only for a separately authorized execution with the frozen derived media in `AF_DATA_ROOT`. All portable orchestration changes are recorded in `docs/portable_orchestration.json`.


CPU closeout: `python -m analyses.post_audit.replay --output ../new-replay`. Output includes every required condition/baseline/Phase3/content audit CSV, source-only diagnostic baseline binding, and corrected historical row predictions. It validates every evidence hash, recomputes scalar features directly from corrected vectors, checks source identities, reparses model responses and recomputes the Phase3 numerator from joined labels. Outputs must be new; immutable historical files are never overwritten. Current payload hashes use POST_AUDIT_REPAIR_MANIFEST_V1.json; the old RELEASE_MANIFEST_V1.json is preserved solely as the v1.0.0 historical receipt.

Uncertainty is post-audit analysis: 2000 cluster bootstrap replicates, NumPy default_rng seed 20261008, percentile 95% intervals. All prespecified conflict clusters, including unresolved trials, are sampled. LISTEN clusters use the underlying UID after stripping the evidence-condition suffix; 3C reuses 3B evidence IDs, so condition is selected from the explicit condition field and target_record_id. MCR/CA-MER clusters keep both presentation orders per source_item_id. The same draws and evaluated identity set are used for M0, diagnostic M0+order, and the frozen pooled model. Paired deltas are model minus each baseline; lower log loss/Brier is better. Single-class AUROC/BA resamples are undefined and counted separately, never imputed. Coverage retains the frozen conflict denominator. No multiplicity-adjusted confirmatory claims or target-based model selection are made.

Verified CPU environment: Python 3.12.10, isolated virtual environment, requirements.txt installation, CPU-only torch wheel selected from the official CPU index. The already-present torch requirement was verified rather than incorrectly treated as missing. Frozen Python 3.12.3 GPU scientific definitions are unchanged. On this Windows host the default pytest temporary directory had an access-denied error; a new writable `--basetemp` outside the checkout was used. That host permission issue did not require changing scientific code.

Numerical replay requires exact row identities, label/support states and denominator accounting, with absolute tolerance 1e-12 for floating-point predictions/features/metrics. Input artifact SHA256 checks remain byte-exact. This permits platform libm roundoff without accepting scientific drift; the verified Windows environment also reproduces the prior corrected prediction CSV byte-for-byte.
